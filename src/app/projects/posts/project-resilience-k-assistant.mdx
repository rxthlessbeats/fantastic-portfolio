## Introduction

**ResiDemy** in the UI is a knowledge-management tutoring platform, receive guided responses grounded in their own document corpus—not generic chatbot answers.

The system couples a **Streamlit** frontend, a **Django 4.2** REST/CMS backend, **OpenAI** embeddings and completions, **Microsoft AutoGen** multi-agent orchestration, and **LanceDB** vector search with **per-user** knowledge stores.

## Problem & users

**Goal:** Help graduate students explore assigned papers and community knowledge objects through conversational guidance—summaries, comprehension checks, document Q&A, and structured learning activities—while preserving instructor-curated content and user-specific uploads.

**Primary users:**

- Students in service-science coursework who need scaffolded reading support
- Community members sharing articles via **LINE** messaging integration
- Administrators managing CMS content, personas, and broadcast workflows

**Frontend (`Residemy/`):** Multi-page Streamlit app—assistant chat, document upload/Q&A, file Q&A, community hub, admin tools—with **LINE OAuth** login, local session storage, and optional audio input.

**Backend (`backend/`):** Django models for `User` (LINE profile), `Document`, `UserDocument`, `UserChatLog`, `AgentPersona`, and `UserActivityList`. APIs expose chat logging, persona generation, activity todos, and the **`simple_rag`** endpoint.

A **`RetrieveUserProxyAgent`** bridges AutoGen tool calls to the Django **`simple_rag`** API so agents query the correct LanceDB tables for each user.

## Retrieval (RAG)

**Vector store:** LanceDB under `userdbs/{user_id}/lancedb` with tables:

- `KnowledgeObject_table` — community / curated knowledge objects
- `Research_paper_table` — user-uploaded research PDFs

**Embeddings:** OpenAI `text-embedding-3-small` with **cosine** similarity search; optional metadata **prefilter** via `where` clauses on structured fields.

**Ingestion:** PDF text via **PyMuPDF**; video pipelines use **OpenCV** / **moviepy** for frame and transcript workflows; responses and summaries are logged to `UserChatLog` for continuity across sessions.

## Platform features

- **Document lifecycle** — upload, list, intro summaries, targeted Q&A, and activity-plan revisions
- **Agent personas** — GPT-generated tutor personalities from uploaded material metadata
- **Activity lists** — structured todo-style learning steps tied to documents
- **LINE integration** — OAuth identity, messaging hooks for sharing articles into the community corpus
- **Django CMS** — editorial content and static assets alongside the API

## Key takeaways

- **Intent routing + specialist agents** scale better than a single monolithic prompt for document-heavy tutoring workflows.
- **Per-user LanceDB** isolates corpora while sharing the same retrieval API and agent toolchain.
- **Bilingual pedagogy** (Traditional Chinese outputs, English/Chinese source papers) is enforced in NLG and document-summary prompts.
- **LINE** lowers friction for a Taiwan-based learning community to push readings into the shared knowledge base.

## Limitations & future work

**Limitations:** Tight coupling between Streamlit session state and backend URLs; AutoGen group latency on multi-hop agent turns; operational cost of embedding every upload at scale.

**Future work:** Unified auth/session layer, agent trace UI for instructors, evaluation harness for retrieval quality, and hardened deployment (containerized API + managed vector DB).
